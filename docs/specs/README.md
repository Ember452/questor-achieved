它们是"参照项目已付过的学费"的可执行形态——Questor 的重写实现以这里的行为规格为蓝本，
坑目录条目 `B-NN` 与测试一一对应（各模块开工时回填测试列）。

## 一、behavior-*.md 模板

文件命名：`behavior-<主题>-<来源>.md`，来源缩写 `fc`=FlowCoder / `ef`=EvoFlow / `wuu`=wuu。
一个文件覆盖一个 Questor 模块的行为域。每条行为规格必须包含全部五段：

```markdown
## <行为名>（一句话祈使句）

- **输入**：调用方给什么（参数/前置状态）。
- **输出**：正常路径返回什么/产生什么副作用。
- **边界行为**：超时、歧义、失败、并发、平台差异——逐条列出；Questor 重写时逐条对照。
- **证据**：`<相对路径>#L<行号>` 或 `<相对路径>::<函数名>`——**落笔前当场验证**。
- **坑**：`B-NN`（如无则写"无"）。

### Questor 采纳决定
沿用 / 调整为 <怎么改> / 拒绝（理由）。此段把"参照"变成"决定"。
```

规则：
- **证据先于落笔**：每条边界行为的证据必须在写入前用 grep/sed 验证存在；行号允许在
  参照项目演进后漂移，但函数名/类名必须仍在。
- 边界行为是本资产的价值所在——正常路径人人会写，**异常分支才是学费**。
- 不搬代码、不搬断言原文；只搬"在什么条件下发生什么"。

## 二、pitfalls.md 规则

坑条目全局编号 `B-01` 起连续递增，**不复用、不跳号**；条目确实不再适用时改成 `moot`，
**不删行也不回号**（`moot` 不计入下限，保证目录只会变大不会空洞）。表字段：

| 字段 | 说明 |
| --- | --- |
| 编号 | `B-NN` |
| 归属模块 | Questor 侧模块名（structure.md §3 清单内），每条**必须**有归属 |
| 一句话 | 坑是什么，用条件句写（"当 X 时，若不做 Y 则 Z"） |
| 来源 | 异常分支 / 平台后缀文件 / remediation 清单 / 测试名 / fix 记录 / CHANGELOG |
| 证据 | 参照项目 `路径#行号或函数名`（落笔前已验证） |
| 对应测试 | Questor 侧测试 `tests/...::test_...`；M1 阶段允许"待落"，**对应模块开工时必须回填** |
| 状态 | open / covered（测试已回填）/ moot（不再适用，保留占号，不计入下限） |

来源五类的 grep 入手点：异常分支（`except`/`else` 支路与错误码）、平台后缀文件
（`*_windows*`/`*_darwin*`/`*_linux*`）、remediation 清单（参照项目 ARCHITECTURE/AGENTS 的
已知债）、测试名（`test_*` 中描述失败场景者）、fix 记录（CHANGELOG 的 fix 条目）。

## 三、cases-*.md 模板

把参照项目的**测试当"失败场景目录"读**：搬场景，不搬断言原文。

| 字段 | 说明 |
| --- | --- |
| 场景名 | 一句话 |
| 参照测试 | `参照仓库路径::测试名` |
| 场景描述 | 它防御什么失败 |
| Questor 归属 | `tests/<层>::<未来测试主题>`（unit/contract/integration/architecture/adversarial/e2e） |
| 状态 | pending / written |

对抗套件（`tests/adversarial/`）的条目优先从坑目录反推：**每条 B-NN 至少一个对抗用例**。

## 四、维护规则

- 扫描期增量落盘：每扫完一个区域即写对应 behavior 文件与坑条目，不等攒批。
- 坑条目数量下限是出口判据（M1a ≥50 且各有归属），但**禁止为凑数收录无证据条目**——
  凑数条目比缺口更有害。
- 契约文档（data-model / protocol）改动导致行为规格过时时，先改契约再改规格，顺序同 AGENTS §七。
