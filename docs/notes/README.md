# 学习笔记（notes）

这里**只放一类内容**：某条链路实际是怎么跑通的（机制解释）。其它都有家，别放错：

| 想写的东西 | 去处 |
| --- | --- |
| 哪里会坏、怎么防 | `docs/specs/pitfalls.md` 的 `B-NN` |
| 为什么这么选、否决了什么 | `docs/adr/` |
| 做到哪一步、何时做什么 | `docs/plans/development-plan.md` |
| 跑分与失败率结论 | `evals/results/` |
| **这条链路怎么跑通的** | 本目录 |

## 三条规矩（不遵守就别写）

1. **必须带锚点**：头部写 `日期:`、`复核于:` 与 `锚点:`，锚点是可 grep 的确切仓库路径（必要时加函数/类名）。
   `日期:` = 写下这条的时间；`复核于:` = 最近一次确认它仍成立的时间（两者分开，否则每次复核
   都在改写历史日期，读者就看不出这条是什么时候写的）。
2. **过期即删**：`scripts/ci/check_notes.py` 会在**代码/配置类锚点**的最后提交日期晚于 `复核于:`
   时判失败——要么重读后更新 `复核于:`，要么删掉它。**不留过期笔记**：过时的机制解释会指挥你写错代码。
   `docs/**` 里的文字锚点只查存在、不参与新鲜度（改一句说明不构成"机制变了"，否则每次编文档
   都要全体笔记陪跑，那是假工）。浅克隆下核查会直接拒跑——没有完整历史就无权下"过期"结论（B-80）。
3. **写法用"预测 → 验证"**：先写下你以为它会怎么跑，再写实际观察到什么、差异在哪、为什么。
   读代码记摘要几乎记不住；被推翻的预测才记得住。文件名 `YYYY-MM-DD-主题.md`。

## 维护时机

绑在已有动作上，不设"每周记笔记"这种会失约的习惯：写 ADR 时顺手一条；勾销里程碑时更新对应条；
`just check` 已经会跑 `check_notes`，所以过期是当场响的，不是攒到年底。

## 边界

本目录**不是**知识仓库、不收录外部教程笔记、不放进度清单。若某条笔记与 overview/ADR 冲突，
以那两份为准并当场修本条（`AGENTS.md` 偏离许可第 3 条：回写）。
