# ADR-0010 — 学习笔记：锚点化 + 过期即删

状态: accepted
日期: 2026-10-11 | 关联: `docs/notes/README.md`、`scripts/ci/check_notes.py`、`AGENTS.md` §四 §七

## 结论

1. 仓库新增 `docs/notes/`，**只承载一类内容：机制解释**（这条链路实际怎么跑通的）。
   失败模式进 `pitfalls.md`、决策进 `adr/`、进度进 `plans/`、跑分进 `evals/results/`——
   四类各有家，不得在 notes 里复述。
2. 每条笔记必须有 `日期:` 与 `锚点:`（可 grep 的确切仓库路径）。
3. **过期即删**由机器执行：`scripts/ci/check_notes.py` 在锚点文件不存在、或**代码/配置类**锚点的
   最后提交日期晚于笔记的 `复核于:`（无该字段时回退到 `日期:`）时判失败；它已接入 `just specs`
   → `just check` 与 CI（逐字一致，见 ADR-0008/0009）。`docs/**` 锚点只查存在性；浅克隆下拒跑。
4. 写法采用**预测 → 验证**：先写下预期，再写实际观察与差异。维护时机绑在已有动作上
   （写 ADR 时、勾销里程碑时），不设"定期记笔记"的独立习惯。

## 理由与取舍

用户的诉求是"开发过程中实时维护一个学习文件夹"。按字面建一个自由笔记目录，三周内必然腐烂：
它不在任何门禁里、没有强制更新点，而**过时的机制解释会指挥后来者（包括三个月后的自己）写错代码**——
本仓库已经因为"不可复核的引用"误判过一次事实。所以取舍很明确：

- **牺牲**：笔记的自由度（不能随手记、不能贴外部教程摘要、不能只写结论不写锚点）。
- **换来**：笔记可以像代码一样被验证——锚点存在性与新鲜度都是机械可判定的。

第二项决定是故意的：`锚点比笔记新 = 笔记过期`。它会把"更新笔记"变成一次红灯修复，而不是
一次没人做的自觉。代价是重构后必须顺手处理笔记（删掉也是处理）。

## 被否决的选项

- **不建 notes，把机制解释塞进 overview**：overview 是契约与约束的唯一入口，混入解释性长文
  会稀释它的可核查性（两表逐行对齐那类规则就没法施加）。
- **建但不加机器检查**：等于制造第四个"事实与文档两张皮"的来源（我们已经为 overview/
  structure/plan 三份文档的互指付过代价）。
- **只查锚点存在、不查新鲜度**：存在但陈旧的笔记恰恰是最危险的形态——它读起来可信。
- **按内容长度或更新频率设指标**：会催生灌水式笔记，与学习目的相反。

## 修订记录：2026-10-12，守卫第一次真响就发现两个设计缺陷

现象：CI 上 `check_notes` 一次性把两条笔记的全部 7 个锚点都判为"10-12 改过 → 过期"，
而本地跑全绿。两个独立成因：

1. **浅克隆让日期语义直接失真**（主因）：`actions/checkout` 默认 depth=1，浅历史下每个
   锚点文件的 `git log -1` 都返回 tip 提交（= 今天）。本地不是浅库，所以永远看不出。
   已记在 B-80；修法：lint job 加 `fetch-depth: 0`，**并且脚本自身先查
   `git rev-parse --is-shallow-repository`，浅库下直接拒跑**——只靠 workflow 配置会等到下次
   有人新建 job 忘记加而不报错；拒跑把前提内置到了工具里（没有完整历史就无权下结论）。
2. **规则太粗，把文字修订当成机制变更**（本条属于 §失效条件 第 3 项，已触发）：我把 ADR-0009
   里"本机装不上 just"改成实况，就让引用该 ADR 的笔记被判过期——但那不构成"机制变了"。
   裁决：新鲜度只适用于**代码/配置类锚点**（`docs/` 之外）；`docs/**` 只查存在。
   同时拆开两个时间：`日期:`（何时写的）与 `复核于:`（最近一次确认仍成立），避免"为了保绿
   而谎改写日期"这个逆向激励。

代价与限制：`复核于:` 本身无法机器验证"你真的重读过"（和原来的日期判定一样靠自觉），
但它至少把"保绿"从一个动作（改日期）换成了另一个动作（读一遍），且不再伪装写作时间。

## 适用条件与失效条件

**适用**：单人开发、文档以可核查为原则、笔记量小（数十条内）。

**触发重新评审**：
1. 笔记数量增长到"过期即删"成为持续负担（比如每次重构要改十几条）→ 改为只保留
   与 ADR 一对一的少量长文，或把机制解释并入代码 docstring；
2. 需要跨仓库共享这些学习记录（那时它就不该住在这个仓库里）；
3. `check_notes` 因锚点粒度太粗频繁误报 → 把锚点粒度下沉到符号级并调整比较方式。
