# ADR-0021 — M2 出口拆分：evals 对照基线移出，内核接口冻结留在 M2.3

状态: accepted
日期: 2026-10-12 | 关联: overview §11（出口判据）、§12（M2/M3 交付）、`development-plan`
M2 三段出口、ADR-0020、`evals/README.md`

## 结论

M2.3 一次装不下"内核四件 + 记录契约 + 体验闭环 + 对照评测"，按**接口优先**重新切分：

| 项 | 归属 | 理由 |
| --- | --- | --- |
| providers / context（Layer1+Layer2+rehydrate）/ serve 雏形 / cli | **M2.3 出口不变** | 全是接口面：ModelPort、记录契约、协议方法名、CLI 入口，晚做都要回改 |
| gesta 记录契约冻结（`context.*` kind + 修订号绑定字段 + `Origin.STEER`） | **M2.3 阶段 A，已完成**（data-model v1.2 + ADR-0017） | 就是本条要求的"接口先于体验活"，实测已落在 providers/context 编码之前 |
| evals N=12 对照 FlowCoder 基线首跑 | **移出 M2.3 出口**，改挂 **M3 出口前**（`evals.yml` 阻塞里程碑不阻塞合入） | 它是"验证已完成的能力"，不改变任何接口形状；挤在 M2.3 会让内核收口被跑批排队 |
| 前端 mock 事件流走通（阶段 I） | 留在 M2 收口（AGENTS §五 前端跟随） | 不依赖真实模型，成本低，且兑现 M2.1/M2.2 两次留痕的承诺 |

同时收紧 §11 出口判据的**可执行性口径**（写进 `evals/README.md`）：

1. 基线只在**双方都能跑通同一形状**的任务上比较：Questor 与 FlowCoder 都以纯文件 +
   路径门档执行的任务参与失败率对比；
2. 需要 Docker/沙箱的任务显式标 `not_in_baseline`，**不从判据里悄悄消失**（overview §11
   自己警告过"否则出口条件会变成无法执行的承诺"）；
3. 干预柱任务标 `not_comparable`：FlowCoder 非交互模式（`flowcoder -p`）没有插话通道，
   且它的权限档是六档（`default|acceptEdits|plan|bypassPermissions|custom|dontAsk`），
   与 Questor 三档不同——基线 adapter 必须走**显式档位映射表**，映射不承诺等价保护。

## 理由与取舍

- 判据不变的部分（"一个真实小任务完整跑通并落盘可回放"）仍留在 M2 出口，只由
  **真实端点单轮 + 跨 turn resume** 证明，不由评测分数证明。
- 代价：对照基线延后一个里程碑，M2 收口时 README 不能引用任何"我们比 FlowCoder 好"的
  数字——这本就是 evals/README 的纪律（无记录不得引用）。

## 被否决的选项

- **保持 M2.3 原样**：把"记录契约冻结"与"跑批"挤在同一批，前者反工会带穿 M3 面板；
  且实测本轮已经出现凭据/余额一类外部依赖导致的阻塞，混在出口里只会拖住内核收口。
- **彻底删掉对照基线**：§11 的"失败率不高于参照"是本项目防自欺的核心机制，删掉等于
  把"可验证"柱降级成主观印象。
- **拿 wuu 当基线**：structure §8 已定（Go 工具链与引擎依赖使脚手架成本高于收益），不改。

## 适用条件与失效条件

**适用**：M2.3 收口与 M3 出口判据的书写。
**触发重新评审**：① 若 FlowCoder 侧出现可注入的插话通道（非交互模式扩展），干预柱任务
可转可比，届时 `not_comparable` 撤销；② 若 Questor 的沙箱（M8）先于基线落地，
`not_in_baseline` 的沙箱类任务重新纳入比较集。
