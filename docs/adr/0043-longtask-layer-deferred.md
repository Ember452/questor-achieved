# ADR-0043 — 长任务/编排/验收层后置为 Phase 6

状态: accepted
日期: 2026-10-14 | 关联: 摘出 `overview.md` §12 M4/M5、ADR-0025/0026/0027/0029/0034、`tests/e2e` 整链、`docs/research/scan-evoflow.md`

## 结论

把 **Plan/Goal/看板/编排派发/验收打回** 这层（原 M4/M5/vigilia 长跑）从 A 阶段主线**摘出，后置为 Phase 6**；规格来源 EvoFlow（读设计不搬码，PolyForm），**围着自研 run 模型重写、不引 LangGraph**。`orchestration`、`vigilia` 大部分、`evidence` 的验收闭环部分随之后置。改判 `overview §12` 中把这些记为"已完成"的口径——那些属将废弃的旧实现。

## 理由与取舍

- 交付优先级"可用 > 扩展 > 性能"：A 阶段先把 wuu 单-agent 可审计工作台跑成 exe，长任务层是第二驱动力、非 MVP。
- 后置显著缩小 A 阶段 surface（一人可维护）。
- 取舍：A 阶段不交付"长跑托管/值班/打回看板"，e2e 整链定义随之改到 Phase 6。

## 被否决的选项

- **A 阶段就做全编排**：surface 过大、与"先可用"冲突。
- **永久不做长任务**：丢掉核心驱动力之一（用户明确要"后期加"）。

## 适用条件与失效条件

**适用**：A 阶段=Phase 1–4。**触发重评审**：若用户在 A 阶段完成前就要长跑托管 → 提前该子层并另排波次。
