# ADR-0030 — 桌面壳改判 Electron；界面/桌面壳主线提前为 Phase U

状态: accepted
日期: 2026-10-13 | 关联: 取代 ADR-0006（壳选型与浏览器面板边界部分）；改判 ADR-0024（桌面壳排期）；
`overview.md` §4/§12/§14/§15、`structure.md` §2/§4/§7/§9/§11、`development-plan.md`（新 Phase U 与 E1 并轨）

## 结论

1. **桌面壳由 Tauri（Rust）改判为 Electron（Node/TS）**。职责仍为纯壳：窗口、`questor`
   sidecar 进程生命周期与崩溃重启、能力声明、图标与打包；**壳内不含业务判断**（此条不变）。
2. **Browser 面板解除 ADR-0006 的"只能是 CDP 镜像、不得说成同一页面"限制**：Electron 自带
   Chromium，Browser 面板可做"面板里那个 tab 即 Agent 正在操作的页面、地址栏真驱动、
   popup 保留 opener 链、一点即暂停接管"的真·同页接管。诚实呈现铁律不受影响——它本就要求
   "按真实能力描述"，现在真实能力变了，描述随之变。
3. **界面 / 动效 / 桌面壳主线提前，立为 Phase U**，紧接已完成的 M5 之后执行；M6/M7/M8 编号不变、
   整体后移到 U 之后；原 `development-plan.md` 的 Phase **E1（界面面全量）并入 U**，E 只保留
   E2（引擎矩阵，随 M6）与 E3（插件生态，随 M7）。
4. **范围边界（防"改一路改到内核"）**：`ui/` React 前端、`serve` 协议与 stdio/WS 传输、
   `schemas` 与生成链、视图注册表（ADR-0020）**全部不变**。本次只动壳的选型与交付排期。

## 理由与取舍

**触发**：ADR-0006"失效条件 #1"白纸黑字——"用户反馈里『接管 agent 正在操作的页面』成为高频
需求 → 重评 Electron/CDP 方案"。用户复核后把目标明确为"复刻 wuu 的界面与桌面壳体验形态"，
其中含内嵌浏览器真接管与 PiP 多窗口——正是当初为省体量而放弃的那块。据此触发本 ADR，合法。

**为什么换壳不需要动内核（这是"不影响后续开发"的核心保证）**：
- 桌面 sidecar 传输是 **stdio NDJSON、与壳无关**。Electron 主进程用 `child_process` 以管道拉
  Python 子进程，与 wuu 用 Electron 主进程拉 Go 子进程同构；`questor serve stdio` 与
  `test_serve_stdio_host` 契约测试原样成立。
- 壳属 `AGENTS.md` §二 (c) 类"UI 与工程外壳"：搬设计与状态表、代码新写——**不在语义/契约 (b) 层**，
  改它不触及数据模型、状态机、协议。
- `structure.md` §11 与 ADR-0024 已把桌面壳推迟——`desktop/` **当前 0 文件**，无沉没代码，
  现在换是成本最低时点，代价只剩 ADR 与文档同步。

**Electron 买到什么**：ADR-0006 当初点名承认、却为体量否决的能力（Chromium 内嵌真接管、
PiP/多窗口/自绘光标/托盘），且这类原生壳能力能直接沿用 wuu 主进程的 TS 写法，不必用 Rust 重造。

**代价（诚实承认，不藏）**：约 +200 MB 体量与内存、自带 Node/Chromium 的升级维护面、
electron-builder 打包链复杂度。这正是 ADR-0006 当年选择 Tauri 躲开的账。取舍翻转的理由是
用户显式指令——"复刻 wuu 桌面壳体验形态"优先级高于"最小体量"。这不是对旧决定的事后否定，
而是前提（第一卖点权重）变了。

**排期翻转的取舍**：桌面壳与界面此前被推到"Phase E、排在 M8 之后"。用户明确界面/桌面壳才是
当前主线；M6/M7/M8（外部引擎、插件生态、可选平台）不推进用户最想拿到的东西。且内核三柱已建成
（M2–M5 + e2e）、界面接口地基已锁死（ADR-0020 视图注册表骨架 + token + 生成类型 + 双宿主契约），
把界面提前**不会回头改已完成模块的接口**（符合 development-plan 横切规则 7"接口面同期、功能面可后置"）——
界面/动效/桌面壳是"功能面"，正是可后置、可重排的那一类。三柱优先级是**判据序**（服务不了三柱的
功能不做），不是**构建序**；提前交付"可见"柱的呈现，不违背优先级。

## 被否决的选项

- **留 Tauri + CDP 镜像**：买不到"同一页面"语义；PiP/多窗口要在 Rust 侧另起一套原生实现——
  用户目标恰是复刻 wuu 那套 Electron 原生壳能力，Tauri 把它变成额外重活。
- **为"将来可能复刻"提前换壳（无当前诉求时）**：违反 §二可逆性三问第 3 条（无第二真实使用者
  不改选型）；本次是用户已明确要求，不是投机。
- **把 E1 整块塞回 M8 之后再动**：等于 M6/M7/M8 全程不做用户最想的东西，与本轮意图相反。
- **换 Electron 同时重排内核/协议**：无必要——传输与契约壳无关，动它们只会把"不影响后续开发"
  的保证破坏掉。

## 适用条件与失效条件

**适用（本期范围）**：桌面壳选型、Browser 面板解除镜像限制、Phase U 插入 M5 与 M6 之间、
E1 并轨 U。§3 范围边界列出的层不动。

**触发重新评审**：
1. Electron 上游出现阻断性 Windows 缺陷，或体量/内存成为硬约束 → 回到 Tauri 或 Web 宿主评估；
2. 主进程 TS 与内核 Python 的边界出现"想往壳里塞业务判断"的冲动 → 违反纯壳纪律，按 R1/§三 拦下；
3. 界面主线暴露出需要新内核能力（新协议方法/事件）→ 那属契约改动，走单独 ADR + 先改 `protocol.md`
   递增版本，不在本 ADR 范围内顺手做。
