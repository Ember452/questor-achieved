# ADR-0006 — 桌面壳选型与浏览器面板边界

状态: accepted（**结论 1 桌面壳选型 = Tauri 与结论 3 浏览器面板 = CDP 镜像，已被 ADR-0030 取代**；结论 2/4/5〔一套前端两宿主、传输双形态契约唯一、默认只绑 127.0.0.1〕仍适用）
日期: 2026-10-11 | 关联: `overview.md` §4 §5 §12 §14、`structure.md` §7、`ui/README.md`、`ADR-0007`、`ADR-0030`（改判本 ADR 的壳选型与浏览器面板边界）

## 结论

1. **桌面壳 = Tauri**（Rust 壳 + `ui/` 一套 TS 前端）。壳的职责收缩为：窗口、`questor`
   sidecar 进程生命周期与崩溃重启、capabilities 声明、图标与打包。**壳内不含业务判断**。
2. **前端只有一套代码**：`ui/` 同时喂桌面与浏览器两个宿主；生成类型进
   `ui/src/rpc/generated/`，CI 断言"重新生成后无 diff"。
3. **Browser 面板延后到 Phase E，且不以"等价体验"为目标**。若将来实现，它只能是
   **CDP 外挂浏览器的镜像 + 输入转发**，不是"面板里那个 tab 就是 Agent 正在用的页面"。
   任何界面文案、文档与 README 不得把镜像描述成同一页面。
4. **传输双形态但契约唯一**：桌面用本机 stdio NDJSON（sidecar），浏览器用网关 WS/SSE；
   方法名、事件形状、错误语义同源，**禁止为浏览器开私有端点**（overview §8 §14）。
5. 本地浏览器宿主**默认只绑 `127.0.0.1`**；对外暴露属 L4 能力，需单独 ADR 并带鉴权。

## 理由与取舍

**为什么不选 Electron（wuu 的方案）**：Electron 的最大好处恰好是 Chromium 内嵌——agent 的
自动化与面板显示跑在同一个浏览器里，于是地址栏/后退/刷新能真驱动、popup 保留 opener 链、
登录态与 profile 可复用、"你一点页面任务就暂停"是天然结果。代价是我们不接受的：
多约 200 MB 体量、自带 Node/Chromium 升级面、打包链复杂度（wuu `desktop/` 241k 行、
95 个脚本正是这条链的价格）。本项目第一卖点是**可审计**（第三柱），不是"替用户抢 Chrome"，
不值得为此背上 Chromium 发行维护。

**Tauri 的代价要写明白**（这才是本 ADR 的实际作用）：

| wuu 的浏览器能力 | Tauri + CDP 镜像下能做到什么 |
| --- | --- |
| 面板里那个 tab 就是 agent 的页面 | 只能镜像串流；点击需转发回 CDP |
| 地址栏/后退/刷新真驱动 | 需自建"反向控制"，非原生 |
| 共享登录 profile | 取决于外挂浏览器实例，不随壳走 |
| 用户输入即暂停任务 | 可实现（转发层拦得到），但**依赖转发路径可靠性**，误判风险更高 |
| `WUU_BROWSER_PROXY` 之类只作用于内嵌浏览器 | 外挂浏览器需自行配置代理 |

结论：浏览器面板**从 M3 交付里摘出**，推到 Phase E；M3 只做 Review / Files / Terminal
三面板——它们的可信度不依赖浏览器实现细节。

**终端为什么不吃这个代价**：Terminal 面板用 `@xterm/xterm` + 后端 PTY，与"同一个进程宿主"
无关，Windows 侧无 PTY 时退回 pipe 的语义（wuu 明写）我们照抄，因此 Terminal 可以早做。

## 被否决的选项

- **Electron**：见上，体量与升级面换不到本项目卖点。
- **PySide/Tkinter 做 GUI**：Python 绑定 GUI 会把"可见"这一柱做得比 wuu/EvoFlow 都弱，
  且前端生态（diff 渲染、流式 Markdown、DAG）全部得重造。
- **两套前端（桌面一套、网页一套）**：必然分叉，等于放弃"一套契约两个宿主"。
- **现在就做浏览器面板**：会把 M3 的关键路径（真接协议 + 修订号绑定）拖进依赖外部浏览器的
  泥潭；且它的正确实现需要 CDP 层先稳定。
- **把镜像说成"同一页面"**：违反 §一 铁律 1 诚实呈现，直接否决。

## 适用条件与失效条件

**适用**：单人本地使用、第一平台 Windows、以可审计为卖点、无重度网页自动化需求。

**触发重新评审的信号**：
1. 用户反馈里"接管 agent 正在操作的页面"成为高频需求 → 重评 Electron/CDP 方案，
   并按 `ADR-0008` 的失效条件同步门禁；**（2026-10-13 该信号已触发：用户把目标明确为复刻 wuu
   界面/桌面壳体验形态，据此落 ADR-0030 改判 Electron，本 ADR 结论 1/3 作废）**
2. Tauri/WebView2 在 Windows 上出现无法绕过的渲染或串流缺陷；
3. 决定做移动端/远程 → 那时"一套契约两个宿主"要扩成 N 宿主，协议版本策略需重开 ADR。

  面板可做真·同页接管。本 ADR 当初为省体量（+约 200 MB / Chromium 升级维护面）而主动放弃
